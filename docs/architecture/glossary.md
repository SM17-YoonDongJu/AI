> 상위: [README](./README.md) · rag.md·database.md·core.md·langgraph.md(+guardrail.md·chatbot.md)의 용어를 쉬운 말로 풀어 정리

## 🎯 한 문장 요약

보험·법률 AI 엔진 문서에 나오는 검색·AI·DB·메시지·보안·보험 용어를, 일상 비유를 곁들여 비전문가도 한 줄로 이해할 수 있게 풀어놓은 낱말 사전이다.

## 📖 이 사전 쓰는 법

- 문서를 읽다가 모르는 단어가 나오면 아래 **카테고리 표**에서 찾으세요. 표는 `| 용어 | 쉬운 설명 |` 형태입니다.
- 각 설명은 "정확한 뜻 + 일상 비유" 순서로 되어 있습니다. 급하면 비유만 봐도 감을 잡을 수 있어요.
- 숫자·차원·기본값(예: 임베딩 1024차원, RRF 상수 60) 같은 **구체 수치는 실제 코드 기준**이라 그대로 믿어도 됩니다.
- **🚧 미구현** 표시가 붙은 용어는 "문서엔 설명돼 있으나 아직 코드로는 안 만들어진 것"입니다. 정직하게 구분해 두었습니다.
- 더 깊게 보려면 각 용어 끝의 안내(예: "→ rag.md")를 따라가세요.

> 이 사전은 뜻만 쉽게 풀 뿐, 원문 문서의 기술 사실을 바꾸지 않습니다.

## 1. 검색 / AI 기초

| 용어 | 쉬운 설명 |
|------|-----------|
| **RAG** (Retrieval-Augmented Generation, 검색증강생성) | AI가 답하기 전에 먼저 관련 문서를 **찾아본 뒤** 그 내용을 근거로 대답하게 하는 방식. 학생이 시험 볼 때 기억만으로 쓰지 않고 교과서에서 해당 쪽을 펴서 보고 답하는 것과 같다. 이 프로젝트의 RAG는 보험 약관·판례·장해분류표를 찾아준다. |
| **LLM** (Large Language Model, 대규모 언어모델) | 방대한 글을 학습해 사람처럼 문장을 이해하고 만들어내는 AI. 아주 많은 책을 읽어 말을 잘하게 된 조수라고 보면 된다. 여기서는 진단 분석·특약 대조·리포트 작성에 쓴다. |
| **임베딩** (embedding) | 문장이나 단어를 **숫자 좌표(벡터)로 바꾸는 것**. 뜻이 비슷한 문장은 지도 위 가까운 위치에 찍히도록 변환하는 작업이다. 이 프로젝트는 문장 하나를 숫자 1024개짜리 좌표로 바꾼다. |
| **벡터** (vector) | 여러 숫자를 한 줄로 늘어놓은 것. 임베딩의 결과물이며, "문장의 위치를 나타내는 좌표"라고 생각하면 된다. |
| **청크** (chunk) | 긴 문서를 검색·저장하기 좋게 잘라놓은 **한 조각**. 책 전체가 아니라 문단 단위로 잘라두면 필요한 부분만 빨리 찾을 수 있는 것과 같다. |
| **namespace** (네임스페이스) | 청크가 **어느 자료에서 왔는지 구분하는 꼬리표**. 이 엔진은 `terms`(약관)·`case`(판례·분쟁조정)·`level`(장해분류표) 세 종류를 쓴다. 서랍마다 라벨을 붙여 섞이지 않게 하는 것과 비슷하다. |
| **프롬프트** (prompt) | AI에게 주는 **지시문/질문**. "너는 보험 분석가다. JSON만 출력해라" 같은 역할·규칙·요청을 담는다. 요리사에게 건네는 주문서라고 보면 된다. |
| **LLM Judge** | 한 AI가 만든 답을 **다른(또는 같은) AI가 채점**해, 근거 문서와 어긋나는지 검사하는 방법. 여기서는 리포트의 인용이 실제 검색 청크와 맞는지 본다. 다만 지금은 "발견해도 지우지 않고 기록만 하는" 관찰 전용이다(fail-open). → guardrail.md |
| **환각** (hallucination) | AI가 근거 없이 그럴듯하게 **지어내는 오답**. 사람이 잘 모르는 걸 아는 척 자신 있게 말하는 것과 같다. 이 엔진은 장해 지급률 숫자를 "약관 원문에 실제로 있을 때만" 인정해 환각을 막는다. |

## 2. DB / 검색 엔진

| 용어 | 쉬운 설명 |
|------|-----------|
| **PostgreSQL** (포스트그레스) | 오픈소스 관계형 데이터베이스(자료를 표 형태로 저장·검색하는 프로그램). 이 프로젝트의 모든 데이터가 여기에 담긴다. 잘 정리된 대형 창고 겸 색인 시스템이라고 보면 된다. |
| **pgvector** | PostgreSQL이 **벡터(좌표)를 저장하고 가까운 것을 찾게** 해주는 확장 기능. 임베딩 검색을 DB 안에서 바로 할 수 있게 해준다. |
| **halfvec** | 벡터를 **절반 정밀도(float16)로 저장**하는 벡터 타입. 숫자를 조금 성기게 저장해 **공간을 절반으로 줄인다**. 세 벡터 테이블 모두 `halfvec(1024)`(1024차원)를 쓴다. → database.md |
| **HNSW** (계층 탐색 그래프) | 수많은 벡터 중 비슷한 것을 **빠르게 근사 검색**하는 색인 구조. 전부 하나씩 비교하지 않고 지름길 지도를 따라 가까운 이웃으로 점프한다. 설정값은 `m=16, ef_construction=64`. |
| **벡터 검색 / ANN** (Approximate Nearest Neighbor, 근사 최근접 이웃) | 질문 좌표와 **가장 가까운 문장 좌표들**을 찾는 검색. "정확히 1등"이 아니라 "충분히 가까운 상위 몇 개"를 빠르게 찾는 방식이라 ANN(근사)이라 부른다. |
| **코사인 유사도** (cosine similarity) | 두 벡터가 **얼마나 같은 방향을 보는지**로 재는 닮음 정도. 방향이 같을수록 뜻이 비슷하다고 본다. pgvector에서는 `<=>` 연산자(코사인 거리, 작을수록 유사)로 계산한다. |
| **tsvector** | PostgreSQL이 본문을 **단어별로 쪼개 만든 전문검색용 색인**. 문서를 미리 단어 목록으로 정리해 키워드 검색을 빠르게 한다. 이 엔진은 Kiwi로 형태소를 나눈 `content_tokens`를 재료로 쓴다. |
| **plainto_tsquery** | 사용자가 친 **평범한 문장을 tsvector 검색용 질의로 바꿔주는** PostgreSQL 함수. 문장을 자동으로 검색 키워드로 정리해 매칭(`@@`)에 쓴다. |
| **GIN 인덱스** | 하나의 항목에 **여러 값(단어·태그 등)이 들어 있을 때** 빠르게 찾도록 만든 색인. 책 뒤 "찾아보기(색인)"처럼 단어→위치를 미리 만들어 둔다. 전문검색·태그·trigram에 쓰인다. |
| **trigram / pg_trgm** | 단어를 **세 글자씩 겹쳐 쪼개** 비슷한 철자를 찾는 기법. "후유장애"와 "후유장해"처럼 오타·표기 차이를 잡아낸다. 오타 보정 사전(`search_terms`) 검색에 쓴다. |
| **similarity** (유사도 함수) | trigram으로 두 단어가 **얼마나 닮았는지 0~1로 매기는** 함수. 이 엔진은 `similarity > 0.4`(0.4 초과, 0.4 정확히는 제외)인 정규 용어만 오타 보정 후보로 쓴다. → rag.md |
| **RRF** (Reciprocal Rank Fusion, 역순위 융합) | 키워드 검색 순위와 벡터 검색 순위를 **하나로 합쳐** 최종 순위를 매기는 방법. 두 심사위원의 등수를 합산해 종합 우승자를 뽑는 것과 같다. 점수 = Σ 가중치/(60 + 등수), 키워드:벡터 = 0.5:0.5. → rag.md |
| **JSONB** | PostgreSQL이 **JSON(중첩 구조 데이터)을 효율적으로 저장·조회**하는 컬럼 타입. 표 한 칸에 여러 항목이 든 상자를 통째로 넣는 것과 같다. 추출 엔티티·입원이력·리포트 초안 저장에 쓴다. |
| **TIMESTAMPTZ** | **시간대(타임존) 정보를 포함한 날짜·시각** 타입. 어느 지역 기준 시간인지까지 함께 저장해 헷갈리지 않게 한다. 생성/수정 시각 컬럼이 이걸 쓴다(UTC 기준). |
| **UUID** | 전 세계에서 **겹치지 않게 만든 긴 식별 번호**. 예: `550e8400-...`. 순번(1,2,3) 대신 아무 데서 만들어도 안 겹치는 고유 이름표라고 보면 된다. 모든 앱 테이블의 기본 키가 UUID다. |
| **TEXT[]** | 문자열을 **여러 개 담는 배열 컬럼**. 한 칸에 "특약1, 특약2, 특약3"처럼 목록을 넣을 수 있다. 가입 특약·태그·근거 목록 등에 쓴다. |
| **인덱스** (index) | 원하는 데이터를 **빨리 찾게 미리 만들어 둔 색인**. 책 뒤 찾아보기처럼, 없으면 처음부터 전부 뒤져야 하지만 있으면 바로 펼친다. |
| **트랜잭션** (transaction) | 여러 작업을 **"전부 성공 아니면 전부 취소"로 묶는** 단위. 은행 이체에서 출금·입금이 둘 다 되거나 둘 다 안 되도록 보장하는 것과 같다. persist가 초안·리포트·쟁점 저장을 한 트랜잭션으로 묶는다. |
| **UPSERT / ON CONFLICT** | "있으면 **갱신**, 없으면 **새로 넣기**"를 한 번에 하는 방식. 같은 열쇠(키)가 부딪히면 덮어쓴다. 리포트 초안을 여러 번 저장해도 한 줄만 남게 해준다. |
| **멱등성** (idempotent, 멱등) | 같은 걸 **여러 번 실행해도 한 번 한 것과 결과가 같음**. 엘리베이터 버튼을 여러 번 눌러도 한 번 부른 것과 같은 것처럼. 재처리돼도 데이터가 중복·꼬이지 않게 하는 핵심 원칙이다. |

## 3. LangGraph / 워크플로

| 용어 | 쉬운 설명 |
|------|-----------|
| **LangGraph** | AI 작업 여러 단계를 **그래프(순서도)로 엮어 실행**하는 도구. "이 단계 → 저 단계, 조건이 이러면 다른 길로" 같은 흐름을 그림처럼 짜서 돌린다. 리포트 워커가 14개 단계를 이걸로 잇는다. |
| **StateGraph** | LangGraph에서 **공용 상태(state)를 들고 도는 순서도**. 각 단계가 같은 서류철을 넘겨받아 자기 칸을 채워 다음으로 넘긴다. 리포트 워커 그래프의 뼈대다. |
| **노드** (node) | 순서도의 **한 작업 단계**. 예: 컨텍스트 불러오기, 진단 추출, 약관 분석. 이 그래프에는 노드가 14개 있다. |
| **상태 / TypedDict** (state) | 그래프 전체가 **공유하는 데이터 묶음**(여기선 `ReportState`). 각 노드가 여기서 필요한 값을 읽고 결과를 채운다. `TypedDict`는 "어떤 키에 어떤 타입이 오는지 미리 정한 파이썬 딕셔너리"다. 돌려 쓰는 공용 서류철이라고 보면 된다. |
| **reducer** (리듀서) | 여러 노드가 **같은 키에 동시에 쓸 때 값을 합치는 규칙**. 이 프로젝트는 노드가 순차 실행이라 동시 쓰기가 없어 reducer를 **쓰지 않는다**(errors만 각자 이어 붙임). → langgraph.md |
| **조건분기** (conditional edge, 조건 엣지) | **상황에 따라 다음 길이 갈리는** 연결. 예: 입력이 차단되면 저장-차단 노드로, 아니면 진단 노드로. 갈림길 표지판이라고 보면 된다. |
| **라우터** (router) | 조건분기에서 **어느 길로 갈지 판단하는 함수**. 노드처럼 등록되진 않고 "판정만" 한다. 이 그래프엔 라우터가 3개 있다(`route_after_input`·`policy_in_db`·`route_after_case`). |
| **ainvoke** | LangGraph 그래프를 **비동기로 한 번 끝까지 실행**하는 호출. 시작 상태를 넣으면 모든 노드를 거쳐 최종 상태를 돌려준다. 워커가 `_graph.ainvoke(state)`로 리포트 한 건을 생성한다. |

## 4. 메시지 / 인프라 (Kafka)

> 표 읽는 법: Kafka는 여러 서버(워커)가 서로 직접 부르지 않고 **메시지를 우체통에 넣어 주고받는** 방식이라고 생각하면 아래 용어가 술술 이어집니다.

| 용어 | 쉬운 설명 |
|------|-----------|
| **Kafka** (카프카) | 서비스들 사이에 **메시지를 안전하게 전달·보관**해 주는 메시지 시스템. 보낸 쪽과 받는 쪽이 서로 몰라도 되는 **공용 우체국**이라고 보면 된다. OCR·리포트 워커가 이걸로 일감을 주고받는다. |
| **토픽** (topic) | Kafka에서 메시지를 **주제별로 담는 우편함**. 예: `report-job`(리포트 일감), `ocr-job-queue`(OCR 일감). 우체국 안 주제별 사서함이다. |
| **프로듀서 / 컨슈머** (producer / consumer) | **프로듀서**는 메시지를 토픽에 넣는 쪽(편지 부치기), **컨슈머**는 토픽에서 꺼내 처리하는 쪽(편지 받아 일하기). 워커는 컨슈머로 일감을 받고 프로듀서로 결과를 보낸다. |
| **오프셋** (offset) | 토픽 안에서 **"어디까지 읽었는지 가리키는 책갈피 번호"**. 메시지마다 순번이 있고, 이 번호로 위치를 기억한다. |
| **오프셋 커밋** (offset commit) | "여기까지 **처리 완료**"라고 책갈피를 저장하는 것. 이 엔진은 처리가 성공한 **뒤에** 커밋해서, 중간에 죽으면 다시 그 자리부터 처리하게 한다(수동 커밋). |
| **at-least-once** (최소 한 번) | 메시지를 **최소 한 번은 반드시 처리**(가끔 중복 가능)하는 보장 방식. 유실은 없지만 재처리가 있을 수 있어, 그래서 핸들러가 **멱등**이어야 한다. |
| **DLQ** (Dead Letter Queue, 죽은 편지함) | 검증 실패나 재시도 소진으로 **처리 못 한 메시지를 따로 모아두는 토픽**(예: `report-job.dlq`). 반송 편지를 버리지 않고 별도 보관함에 넣어 원본을 잃지 않게 한다. |
| **파티션 키** (partition key) | 메시지를 **어느 칸(파티션)에 넣을지 정하는 열쇠값**. 같은 키(예: 같은 report_id)는 같은 칸으로 가서 **순서가 지켜진다**. 같은 고객 편지를 같은 담당 창구로 보내는 것과 같다. |
| **우아한 종료** (graceful shutdown) | 종료 신호(SIGTERM/SIGINT)를 받으면 **하던 일을 마무리하고 깔끔히 멈추는** 것. 갑자기 코드를 뽑지 않고 "지금 손님까지만 받고 문 닫기"처럼 안전하게 끝낸다. |

## 5. 비동기 / 파이썬

| 용어 | 쉬운 설명 |
|------|-----------|
| **async / await** (비동기/대기) | 오래 걸리는 일(DB·네트워크)을 **기다리는 동안 다른 일을 하도록** 하는 파이썬 문법. 라면 물 끓는 걸 지켜만 보지 않고 그동안 설거지하는 것과 같다. `await`는 "여기서 결과 나올 때까지 잠깐 양보"라는 뜻. |
| **asyncpg** | PostgreSQL을 **비동기로 빠르게** 다루는 파이썬 라이브러리. 여러 DB 요청을 기다리며 놀지 않고 겹쳐 처리해 성능이 좋다. |
| **커넥션 풀** (connection pool) | DB 연결을 매번 새로 만들지 않고 **미리 몇 개 만들어 돌려 쓰는** 저장고. 손님마다 새 컵을 사지 않고 공용 컵을 씻어 재사용하는 것과 같다. 기본 2~10개를 유지한다. |
| **httpx** | 파이썬에서 **HTTP 요청을 비동기로 보내는** 라이브러리. AI 서버(Ollama 등)를 부를 때 쓴다. |
| **pydantic** | 데이터가 **정해진 형식(타입)에 맞는지 자동 검증**해 주는 라이브러리. 들어온 메시지가 규격에 맞는지 문지기처럼 확인하고, 어긋나면 걸러낸다(Kafka 메시지 검증에 사용). |
| **지연 생성(lazy) / 싱글턴** (singleton) | **지연 생성**은 "필요할 때 처음 한 번만 만들기", **싱글턴**은 "프로그램 전체에서 하나만 두고 공유하기". AI 클라이언트·DB 풀·형태소 분석기(Kiwi)를 이렇게 한 번만 만들어 계속 재사용한다. 사무실 공용 복합기 한 대를 다 같이 쓰는 것과 같다. |

## 6. 보안 / 개인정보

| 용어 | 쉬운 설명 |
|------|-----------|
| **PII** (Personally Identifiable Information, 개인식별정보) | 주민번호·전화·카드번호·이메일처럼 **누군지 특정할 수 있는 정보**. 유출되면 안 되는 민감 데이터라 특별히 조심해서 다룬다. |
| **마스킹** (masking) | PII의 일부를 **별표(*)로 가리는** 것. 예: `010-****-5678`, 주민번호 앞 6자리만 남기기. 통장 사본에서 계좌 일부를 가리는 것과 같다. |
| **정규식** (정규표현식, regex) | 글자 **패턴을 찾아내는 규칙 문법**. "숫자 3개-숫자 4개-숫자 4개면 전화번호" 같은 규칙으로 PII를 자동으로 찾아 마스킹한다. |
| **NER** (Named Entity Recognition, 개체명 인식) | AI가 문장에서 **이름·주소 같은 개체를 알아내는** 기술. 정규식으로 못 잡는 비정형 PII(사람 이름 등)를 잡으려는 용도지만, **🚧 이 프로젝트에선 아직 미구현**(현재는 정규식만 동작)이다. → guardrail.md |
| **가드레일** (guardrail) | AI가 **위험하거나 부정확한 결과를 내지 않게 막는 안전장치**. 입력(PII 마스킹·주제 이탈 차단)·생성(단정 금액을 범위 표현으로)·출력(고지문 삽입·인용 검증) 3단계로 되어 있다. 도로 옆 가드레일처럼 벗어나지 않게 잡아준다. |
| **고지문** (disclaimer) | 리포트 맨 앞에 넣는 **법적 안내 문구**. "정확한 보험금 지급 여부는 담당 손해사정사의 검토 후 확정됩니다" 같은 문장으로, AI 결과가 확정이 아님을 알린다. 이미 있으면 중복으로 넣지 않는다(멱등). |
| **JWT (RS256)** | **로그인 상태를 증명하는 디지털 출입증**(JSON Web Token). RS256은 그 출입증에 **위조 방지 서명**을 하는 방식이다. 챗봇이 연결될 때 이 토큰을 검사해 정당한 사용자만 받고, 무효면 거부(`4401`)한다. → chatbot.md(계획 단계) |
| **SSE-S3** (Server-Side Encryption with S3-Managed Keys) | AWS S3가 파일을 저장할 때 **자동으로 암호화**해 주는 기능(열쇠 관리도 S3가 대신). 창고에 물건을 넣으면 알아서 자물쇠를 채워주는 것과 같다. 이 프로젝트에서 파일 저장(S3)은 Spring Boot 게이트웨이가 담당한다. |

## 7. 보험 도메인

| 용어 | 쉬운 설명 |
|------|-----------|
| **손해사정 / 손해사정사** | **손해사정**은 사고로 받을 보험금이 얼마인지 따져 정하는 일, **손해사정사**는 그걸 전문으로 하는 사람이다. 이 AI 엔진은 손해사정사의 검토를 **돕는 초안**을 만든다(최종 확정은 사람이 한다). |
| **특약** | 기본 보험에 **추가로 붙이는 보장 옵션**. 예: 후유장해 특약, 수술 특약. 기본 세트에 얹는 추가 토핑이라고 보면 된다. "가입 특약"은 고객이 실제로 든 옵션 목록이다. |
| **면책** | 보험사가 **보험금을 주지 않아도 되는 사유**. 약관에 "이런 경우엔 지급 안 함"으로 정해둔 예외다. |
| **후유장해** | 치료 후에도 **남는 신체·정신 장해**. 눈·귀·팔·다리 등 부위별로 얼마나 남았는지에 따라 보험금이 달라진다. `requires_disability_review`가 참이면 이 검토 경로로 간다. |
| **장해분류표 / 지급률** | **장해분류표**는 어떤 장해에 몇 %를 주는지 정한 표, **지급률**은 그 퍼센트다. 예: 특정 장해 = 지급률 30%. 금감원 표준 장해분류표는 개정판마다 내용이 달라, 계약 체결일에 맞는 판을 골라 쓴다. |
| **판례 · 분쟁조정례** | **판례**는 법원 판결 사례, **분쟁조정례**는 금융감독원이 보험 분쟁을 조정한 사례다. 비슷한 과거 사례를 근거로 대는 데 쓴다(`case` namespace). |
| **KCD / ICD 코드** | 질병·상해에 붙이는 **표준 분류 코드**(ICD는 국제 표준, KCD는 그 한국판). 병명을 숫자·문자 코드로 통일해 정확히 가리킨다. 진단 추출 시 `icd_codes`로 뽑는다. |
| **진단서 / 보험증권 / 지급결과안내문 / 청구서** | 처리 대상 문서 4종. **진단서**(의사가 쓴 병명·소견, `diagnosis`), **보험증권**(가입 내용 증명, `policy`), **지급결과안내문**(보험사가 얼마 준다고 안내, `payout_notice`), **청구서**(보험금 청구, `claim`). OCR로 글자를 읽어 처리한다. |

## 8. 모델 / 서빙

| 용어 | 쉬운 설명 |
|------|-----------|
| **Ollama** (올라마) | AI 모델을 **내 서버(GPU 노드)에서 직접 돌리게** 해주는 실행 도구. 외부 클라우드 대신 자체 장비에서 LLM을 띄워 HTTP로 부른다. |
| **EXAONE** (엑사원) | 이 엔진이 **글 생성·분석에 쓰는 LLM** 후보(예시로 지정). 진단 분석·리포트 작성 등에 쓴다. 다만 실제 모델명은 코드에 하드코딩하지 않고 **환경변수로 주입**한다(기본값은 빈 문자열). |
| **qwen3:embedding** | 이 엔진의 **기본 임베딩 모델**(문장→1024차원 좌표 변환 담당). 검색용 벡터를 만든다. |
| **BGE-M3** | qwen3 임베딩이 실패했을 때 쓰는 **예비(폴백) 임베딩 모델**. 역시 1024차원이라 벡터공간이 맞는다. 주 모델이 고장 나면 대신 나서는 예비 타자라고 보면 된다. → rag.md |
| **OpenAI 호환 API** | OpenAI가 정한 **요청/응답 형식을 그대로 따르는** 인터페이스(`/chat/completions`·`/embeddings`). 이 규격만 맞으면 Ollama든 다른 서버든 코드를 안 바꾸고 붙일 수 있다. 표준 콘센트 규격 같은 것. |
| **vLLM / TEI** | 모델을 **빠르게 서빙(제공)하는 다른 엔진들**(vLLM=텍스트 생성, TEI=Text Embeddings Inference=임베딩 전용). ai_client가 OpenAI 호환이라 Ollama 대신 이들로도 바꿔 붙일 수 있다. |

## 9. 아키텍처 (전체 배치)

| 용어 | 쉬운 설명 |
|------|-----------|
| **Spring Boot 게이트웨이** | 프런트엔드와 처음 만나는 **정문 서버**(자바 기반). 파일 업로드·로그인(JWT)·S3 저장·Kafka로 일감 발행을 맡는다. 이 Python AI 엔진과는 **별도 범위**로, 여기선 손대지 않는다. |
| **FastAPI** | 파이썬으로 **웹 API·WebSocket 서버를 빠르게** 만드는 프레임워크. 챗봇이 이걸로 실시간 연결을 받도록 설계돼 있다(**🚧 본체는 아직 미구현**). |
| **WebSocket** | 서버와 클라이언트가 **연결을 계속 열어두고 양방향으로 주고받는** 통신. 매번 새로 문을 두드리는 대신 전화선을 계속 연결해 두는 것과 같다. 챗봇 대화에 쓸 예정이다. |
| **Redis** (레디스) | 데이터를 **메모리에 두어 아주 빠르게 읽고 쓰는** 저장소. 챗봇 세션(만료 24시간)과 최근 대화 요약 캐시를 여러 서버(Pod)가 공유하는 데 쓸 계획이다. 접수처의 빠른 메모판이라고 보면 된다. |
| **AWS S3** | 아마존의 **파일 보관 창고**(객체 스토리지). 약관 PDF·표 파일 등을 넣어두고 열쇠(key)로 꺼낸다. 저장·발급은 Spring Boot가 담당한다. |
| **ALB** (Application Load Balancer) | 들어오는 요청을 **여러 서버에 나눠 보내주는 교통정리 장치**(아마존 로드밸런서). 챗봇의 `/ws/chat` 경로 요청을 FastAPI로 라우팅한다. |
| **GPU 노드** | **AI 모델 계산을 담당하는 고성능(그래픽카드 탑재) 서버**. LLM·임베딩처럼 무거운 연산은 여기서 돌린다. 챗봇 서버 자체는 GPU가 필요 없는 일반 노드에 두고, 계산만 GPU 노드에 HTTP로 맡긴다. |
