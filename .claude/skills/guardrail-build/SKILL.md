# Guardrail Build

노션 06번. 리포트(05)·챗봇(12)이 **함수 호출**로 쓰는 공용 모듈(`src/guardrail/`). 독립 서비스가 아니다. 개인정보보호와 법적 안전성이 이 도메인의 핵심 제약이므로, 가드레일은 "있으면 좋은 것"이 아니라 필수 경로다.

## 3단계

### 입력 가드레일
- 정규식 + NER로 **PII 탐지·마스킹**: 주민번호·계좌번호·전화번호·이름·주소. **주민번호는 앞 6자리만 보존**, 나머지 마스킹.
- 보험·법률 **도메인 외 질문**(부동산·주식 등)은 차단 메시지 반환.
- 마스킹된 텍스트만 downstream(RAG·LLM)으로 넘긴다.

### 생성 가드레일
- LLM 생성 중 **단정적 금액 표현**("○○만원 받습니다", "보험금은 ○○원입니다") 실시간 탐지 → "참고 추정 범위: ○○만원 ~ ○○만원"으로 치환.
- 모든 사실 주장에 `[조항번호][판례번호]` 형식 인용을 강제(프롬프트 제약).

### 출력 가드레일
- **법적 고지문** 자동 삽입: "본 분석은 참고용이며 법적 효력이 없습니다. 정확한 보험금 지급 여부는 담당 손해사정사의 검토 후 확정됩니다."
- **LLM Judge(Qwen3 MoE)** — 리포트 한정: 인용 조항번호와 실제 청크 원문 일치 검증. 불일치 섹션은 `[인용 검증 실패 — 삭제됨]`으로 치환.
- **챗봇에는 LLM Judge 미적용** (고지문·단정표현 치환만).

## 구현 원칙
- 호출자별로 적용 단계가 다르다 — 인터페이스를 단계별 함수로 쪼개 리포트/챗봇이 필요한 것만 조립하게 한다.
- LLM Judge는 `core/ai_client.py`(Ollama Qwen3 MoE) 사용. 타임아웃 시 해당 섹션을 **보류 표기**(삭제하지 않음) 후 로깅.
- PII 마스킹 규칙은 `ocr-engineer`의 입력단과 **동일 정의**를 공유해야 한다 — 두 곳에서 어긋나면 한쪽이 PII를 흘린다.
- 마스킹 전 원문을 로그에 남기지 않는다.

## 검증
- 주민번호 앞 6자리 보존 + 나머지 마스킹 정확성.
- 도메인 외 질문 차단.
- 단정 금액 표현이 추정 범위로 치환되는지.
- 잘못된 인용을 LLM Judge가 잡아 섹션을 치환하는지(리포트), 챗봇엔 미적용인지.
