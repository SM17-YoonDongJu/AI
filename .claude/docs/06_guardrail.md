## 참여 컴포넌트

- **가드레일 모듈** (공용 Python 모듈): 입력·생성·출력 3단계 가드레일 실행
- **NER 모델** (로컬): PII 탐지 보조
- **LLM Judge** (EXAONE): 출력 단계 인용 환각 검증

독립 서비스가 아닌 공용 Python 모듈이다. 05번 리포트 생성(Kafka 워커)과 12번 챗봇(FastAPI) 양쪽에서 Python 함수 호출로 사용한다. 가드레일 모듈 자체는 Frontend·Spring Boot·Kafka와 직접 통신하지 않는다.

## 소프트웨어 레이어 구조

**[입력 가드레일]**

사용자 입력 텍스트(OCR 결과 및 챗봇 메시지)에 적용한다. 정규식과 NER 모델로 주민번호·계좌번호·전화번호·이름·주소를 탐지하고 마스킹한다. 주민번호는 앞 6자리만 보존하고 나머지를 마스킹한다. 보험·법률 도메인 외 질문(부동산·주식 등)은 차단 메시지를 반환한다.

**[생성 가드레일]**

LLM이 생성한 텍스트에서 단정적 금액 표현("○○만원 받습니다", "보험금은 ○○원입니다" 등)을 탐지하여 "참고 추정 범위: ○○만원 ~ ○○만원"으로 치환한다. 모든 사실 주장에 `[조항번호][판례번호]` 형식의 인용을 포함하도록 프롬프트를 강제한다.

**[출력 가드레일]**

완성된 리포트 또는 챗봇 응답에 법적 고지문을 자동 삽입한다. 고지문은 "본 분석은 참고용이며 법적 효력이 없습니다. 정확한 보험금 지급 여부는 담당 손해사정사의 검토 후 확정됩니다."이다. 리포트 생성의 경우 LLM Judge가 인용 조항 번호와 실제 청크 원문의 일치 여부를 검증하며 불일치 발견 시 해당 섹션을 `[인용 검증 실패 — 삭제됨]`으로 치환한다. LLM Judge는 챗봇에는 적용하지 않는다.

## 데이터 흐름 (순서)

**리포트 생성 시:**

1. 사용자 입력 → 입력 가드레일 (PII 마스킹·도메인 차단)
2. LLM 생성 중 → 생성 가드레일 (단정표현 치환·인용 강제)
3. 리포트 초안 완성 → 출력 가드레일 (고지문 삽입·LLM Judge 검증)

**챗봇 시:**

1. WebSocket 수신 메시지 → 입력 가드레일 (PII 마스킹·도메인 차단)
2. LLM 완성 응답 → 생성 가드레일 (단정표현 치환 — 비스트리밍, 완성 텍스트 일괄 검사)
3. 응답 완성 → 출력 가드레일 (고지문 삽입, LLM Judge 미적용)
